AMICA PRODUCT AND IMPLEMENTATION PLAN
23 November 2026 | Windows desktop | Proposed roadmap

1. PRODUCT DIRECTION

Amica should feel like a friend who gets to know you over time. It should pick
up on useful details in ordinary conversation, form memory nodes on its own,
connect related details, and bring them up when they help. The same app should
give you a calm fullscreen view when you step away and let you operate Windows
by voice or text when you return.

The attached image is visual reference material. Its large tile, analog clock,
rounded translucent cards, and blue-purple tint inspire the composition. The
thermostat, intercom, lock, and lights in the image are labels in the reference.
Amica's tiles should show its own clock, timers, orb, and desktop tools with
original proportions, artwork, and controls.

Amica already has typed chat, spoken conversation with Aoede, SQLite conversation
history and saved notes/preferences, a memory map, clock and calendar views,
timers, a reactive orb, media controls, an app launcher, basic window actions,
and PC stats. Build on those features. The command catalog at the end specifies
proposed behavior, including examples for features that already exist.

Project constraints
  Use Rust for application code, Slint as the sole GUI framework, and SQLite
  via Rust for local persistence. Keep feature files together and omit comments
  in source code. Reuse the existing database and migrate its schema without
  losing saved data.

2. THE CONVERSATIONAL FRIEND

Conversation
  - Give the user one timeline across typing and Aoede voice. Switching from
    voice to text should continue the topic and preserve any draft. Show optional
    captions and a visible microphone state. Let the user interrupt playback and
    recover a turn after changing microphones or losing the connection.
  - Match Filipino, English, and Taglish naturally. Offer Auto, Filipino,
    English, and Taglish preferences. Offer Short, Normal, and Detailed reply
    settings and accept one-off requests such as "Taglish lang, short answer."
  - Give Amica three useful ways to respond: listen, help think it through, or
    help act. When someone's venting, let them choose whether they want ideas.
    Ship a morning check-in, study buddy, and end-of-day recap as optional
    conversation starters. Keep reminders and recurring check-ins opt-in.
  - Add named conversations, search and resume, and a private session with no
    local transcript or memory formation. Show a clear indicator while the
    private session is active. Keep raw audio out of persistent storage by
    default. Use completed transcripts for voice memory.

Daily usefulness
  - Connect the existing timers and notes to reminder notifications, simple
    to-do lists, and user-approved routines. Separate local reminders from the
    current calendar grid, which provides dates. Add calendar integrations later
    if there is demand. Keep schedules and timer deadlines working offline.
  - Provide compact conversation shortcuts for brainstorming, explanations,
    language practice, planning, and rewriting. Preview a message for review
    when asked to draft one. Add opt-in summaries of user-selected text later.

3. AUTONOMOUS MEMORY AND THE MEMORY MAP

How Amica gets to know you
  Amica notices durable details in completed typed or spoken conversations.
  For example, saying “Mas gusto kong mag-aral kapag tahimik” is enough to form
  a preference node. The conversation continues normally while the node is
  created in the background. Future replies can use that preference when it
  fits. Memory formation runs automatically in standard conversations, with a
  first-run explanation and an off switch in Settings. Users can correct, pin,
  or forget nodes whenever they want.

What a node represents
  - Preference: “Likes quiet study sessions.” Scope it to studying so it stays
    compatible with preferences such as music for exercise.
  - Goal: “Prepare for a Rust quiz.” Track the user's last stated progress and
    an optional due date or completion state.
  - Project: “Amica.” Keep durable decisions and current milestones connected
    to the project so they can be recalled together.
  - Routine: “Usually reviews notes before bed.” A routine in memory describes
    a habit. Running a Windows routine still requires separate authorization.
  - Interest: “Enjoys drawing.” Connect it to related goals or projects when
    the conversation provides evidence for that connection.
  - Short-lived context: “Wants music today.” Keep it in the current thread or
    give it an expiry tied to the stated date. A passing mood, joke, question,
    or imagined scenario can stay in conversation context.

How nodes form, change, and get recalled
  1. Process a finished user message or a finalized voice transcript in a
     background worker. Each candidate contains the claim, category, scope,
     exact source turn and supporting excerpt, and an optional expiry. Use
     Amica's replies for conversational context. Use the user's words as the
     evidence for claims about them. Exclude quoted material and app content
     from automatic memory formation. Keep credentials and similarly sensitive
     details out of automatic nodes. When capture is off or a session is private,
     skip processing and cancel any pending writes for the affected turns.
  2. Create durable nodes from clearly stated details. A weak inference stays
     tentative until supported by later turns and is excluded from normal
     recall. Deduplicate by meaning, category, and scope. Support Filipino,
     English, and Taglish phrasing for the same concept. Replays of a voice
     turn or a retry of the worker must be safe to process more than once.
  3. Reinforce an existing node when another turn supports it. Connect nodes
     using named relationships such as belongs to, supports, or supersedes
     when the evidence supports the connection. A clear correction replaces
     the active detail and keeps the old one out of normal recall. When two
     claims can both be true in different contexts, keep both scopes. Resolve
     ambiguous conflicts when they matter to an answer.
  4. On each turn, retrieve a few relevant active nodes from SQLite. Rank by
     relevance, scope, and evidence, using recency to break ties. Use a brief
     reference when it helps the current conversation. If uncertain, say what
     was mentioned and ask a focused question. Reminders and desktop actions
     still use their own explicit requests or approved routines.
  5. Expire temporary nodes and remove them from recall. If a source turn is
     deleted, remove its evidence and any node or link left without support.
     Forgetting a node removes it from the graph and recall, along with its
     derived links and index entries. Skip that node when reprocessing old
     history. The user can also choose whether to delete its original messages.

Example across conversations
  Monday: “May Rust quiz ako sa Friday. Mas gusto kong tahimik tuwing nag-aaral ako.”
    Create a Rust quiz goal, with the date resolved in local time, and a quiet
    study preference. Link the preference to the goal with a supports edge.
  Wednesday: “Ano magandang gawin pagkatapos ng dinner?”
    If preparation is still relevant, Amica can suggest a short, quiet Rust
    review. The user can open the memory used and see the original line.
  Later: “Actually, okay ang lo-fi kapag nagbabasa. Tahimik pa rin dapat kapag
    nagme-memorize ako.”
    Update the study preferences by activity. When the user says the quiz is
    finished, mark the goal completed and stop resurfacing it as upcoming.

How it looks and feels
  - Extend the existing rotating Memory Map. Give goals, preferences, projects,
    routines, and interests distinct labels and group related nodes. Briefly
    highlight a newly formed node when the map is open. Selecting it shows its
    sources, related nodes, last update, and history of changes. Provide a
    searchable list view with the same controls for keyboard and screen-reader
    users, and respect reduced motion.
  - Add a Recent Memories view with Edit, Pin, Forget, and Open Source. Show
    which nodes Amica learned from conversation and which were added by hand.
    Keep the Saved view for user-authored notes and explicit preferences.
    Settings should expose automatic memory, pause, and clear learned memories.

Implementation and quality checks
  - Extend src/memory/ with extraction, SQLite storage, retrieval, and graph
    data. Keep the existing saved_items table. Add stable IDs for finalized
    chat turns and store memory nodes, evidence, and typed links. Use a single
    transaction to update a node, its evidence, links, and searchable text.
    Start with new conversations and preserve existing notes and preferences.
  - Exercise the full lifecycle with typed and spoken examples. Verify that an
    ordinary remark creates a node, repeated mentions reinforce it, changes
    update it, expired items stop surfacing, private turns create no nodes, and
    forgetting survives restart. Test quoted text, jokes, misunderstood voice
    input, and topic changes so they do not become persistent facts. Measure
    correct capture and useful recall separately across the three languages.

4. HOME VIEW AND SCREENSAVER

Home view
  - Give the Home screen the reference's tile hierarchy using Amica's identity.
    Use a large left tile for the orb, current voice state, and a Talk action.
    Stack an analog clock/date and timer tile at right. Use three bottom tiles
    for Focus, Now Playing, and Command Palette. Reuse the orb's palette and
    carry navy, indigo, and lavender through the cards. Use a soft gradient
    backdrop, layered translucent fills, and accessible contrast in Slint.
  - Let cards reflow to a single column at narrow widths. Keep a visible focus
    ring, large touch targets, readable numerals, and keyboard navigation.
    Show values only when there is real data. The calendar/timer tile can show
    the local date or the next active timer with time remaining.

Screensaver
  - Take inspiration from macOS screensavers for slow fullscreen motion and a
    graceful return to the desktop. Add two presets. Ambient shows a large
    clock/date, softly moving color and orb, and optionally the active timer
    countdown. Dashboard uses the Home tile arrangement with clock, timer,
    orb, and media status. Hide
    private text, notification contents, and transcripts in both presets.
  - Ship manual entry, a Preview button, and optional idle activation after
    5, 10, 15, or 30 minutes in the first release. Use Windows session idle
    time and skip automatic entry during active voice, presentation, or
    fullscreen media. Start with the monitor that contains Amica, then add
    primary/all-monitor options.
    Exit on Escape or physical input and restore the visible window state.
    Use visible physical interaction to return from Ambient before talking.
  - Release the microphone and end the voice session when the saver enters. Let
    Windows manage display sleep and lock. A later optional Lock on Exit setting
    can call the Windows lock action. Support reduced motion, a dim-on-battery
    option, gentle tile drift for static content, and a fallback for missing
    media/timer data. Keep idle rendering coalesced and low power.
  - Store timeout, preset, motion, privacy, and monitor preferences in SQLite.
    Build this in src/screensaver/ with a Slint component and Rust idle and
    lifecycle logic. Consider Windows .scr integration only after testing the
    in-app mode on different monitors, scaling levels, and sleep/wake cycles.

5. WINDOWS CONTROL

Execution model
  - Route text, command palette, approved routines, and recognized voice
    requests to one Rust dispatcher. Keep action IDs, typed arguments,
    English/Filipino/Taglish examples, behavior, prerequisites, and permissions
    in a shared catalog. Put feature-specific definitions beside each handler.
    Reuse src/actions/ for dispatch and src/desktop/ for Windows integration.
    Give substantial features such as routines their own folders.
  - Resolve known typed commands and palette actions locally so they work
    offline. Keep validation and execution in the dispatcher when the
    conversation needs help interpreting an ambiguous request.
  - Use native Windows APIs for windows, displays, audio, and files where
    possible. Use Windows UI Automation for accessible elements by name, role,
    and scope. Use SendInput for mouse, wheel, and key input in the active user
    session. Use a labeled grid or numbered overlay for apps that do not expose
    controls. Ask which target when there are multiple matches. Show the chosen
    window in the command bar. Handle monitor coordinates, negative origins,
    mixed DPI, and focus changes before sending input.
  - Add Desktop Control mode with visible start/stop state. Quick low-impact
    actions run on explicit request. For delete, overwrite, send, power, bulk
    changes, or costly actions, show the exact target and ask the user to
    confirm the current action in Amica. Apply this to existing restart and
    shutdown paths, including speech. Distinguish "start the screensaver",
    "close Amica", "sleep the PC", and "shut down the PC" with explicit intents.
  - Keep the executor within the signed-in user's interactive session and its
    normal privileges. Locked desktops and protected or elevated surfaces may
    be unreachable. Keep authentication and administrative prompts in Windows.
    Treat page text, screenshots, file content, memory, and app labels as data.
    Only the user's current request or an approved routine can authorize a step.
  - Give every run a Stop control. Revalidate focus and target before each
    action, expire stale voice requests, serialize input, and release injected
    mouse buttons and keys on interruption. Report completion from the local
    action result. Store redacted results and time in a local action history,
    omitting private typed text, clipboard contents, and keys. Deduplicate
    requests across retries. Show undo when the action actually supports it.

Feature sequence
  - Start with pointer movement, hover, left/right/double click, scrolling,
    drag, a grid overlay, hotkeys, text insertion, and window/app switching.
    Keep "click here" scoped to the current pointer and "click Save" scoped
    to the active or explicitly named app. Show matches for ambiguous labels.
  - Add File Explorer, browser navigation, clipboard, Notepad, and audio and
    display controls. Resolve common folders by Windows known-folder IDs.
    Treat observed UI support as the capability boundary and show missing app
    or unavailable feature errors. Use a few supported apps to validate each
    adapter before broadening. Keep app installation and credentials manual.
  - Add user-defined routines composed of typed actions, such as Focus, Study,
    and End of Day. Show ordered steps and a preview. Stop on failed steps and
    show which completed. Revalidate before continuing. Constrain repeat counts
    and durations. Prompt when a workflow reaches an action needing consent.
    Start Focus with a 25-minute timer, open the chosen editor, and optionally
    pause playback. Start Study with a named folder, two chosen apps, and a
    reading timer. End of Day can save the current layout and show tomorrow's
    first local task. Save or close work through the app's normal interactions.

6. RELEASE ORDER AND DEFINITION OF DONE

Release 0.1 refinement | Conversation + automatic memory
  Unify typed and spoken conversation history. Add automatic preference and
  goal nodes, source links, recall across conversations, and the first version
  of Recent Memories. Add the private session, memory controls, and the ability
  to correct or forget a node. Confirm that typed and spoken remarks can form
  a memory automatically and that reloading Amica preserves the result.

Release 0.2 | Home + screensaver + pointer controls
  Ship original Home tiles and two fullscreen presets. Deliver the pointer,
  click, wheel, keys, window-switching, and overlay actions. Exercise the core
  command set in a test window and with mixed-DPI monitors. Target 25 high-use
  actions, each with English, Filipino, and Taglish examples and an expected
  outcome. Confirm keyboard-only access, saver exit, and offline typed input.

Release 0.3 | Everyday tools + expanded memory graph
  Expand to 60 action families across apps, Explorer, browser, clipboard,
  media, and settings. Add reminders, searchable conversations, project and
  routine nodes, relationship editing, and activity-specific preferences.
  Verify migrations against an existing SQLite profile. Exercise connection
  loss, clipboard privacy, target changes, and retries in a test workspace.

Release 0.4 | Routines + full catalog coverage
  Progress toward 120 command families using the appendix as the acceptance
  backlog. Connect the catalog to the palette, show prerequisites, and deliver
  named routines and accessibility improvements. Run all 1,200 examples against
  intent resolution. Run representative executions with test windows and files.
  Track intent accuracy by language and execution success by app. A release
  passes only when common actions have clear outcomes, unsupported actions
  explain the limitation, and sensitive operations cannot run on stale approval.

First vertical slice to build
  Say “Mas gusto kong tahimik kapag nag-aaral ako” during a voice conversation.
  Open the Memory Map and find the preference and its source. Start a new typed
  chat and ask for a study plan. Check that Amica suggests a quiet session when
  relevant. Edit or forget the node, then repeat the request to verify that the
  change takes effect. Follow with a focus timer, Ambient, and a Notepad scroll
  command in the screensaver and desktop-control release.

APPENDIX. COMMAND CATALOG

1,200 concrete command examples across 120 action or conversation families.
Packs 01–10 cover 1,000 Windows commands. Packs 11–12 cover 200 requests
for conversation and Amica's local features. The catalog pairs each family
with its expected behavior and uses different targets, values, and situations.
It is a development and acceptance backlog. App names, control labels, files,
and saved routines are fixtures. Create them in a disposable test workspace.
Missing prerequisites or unsupported actions should produce clear feedback.

EN is English, FIL is Filipino, and TG is Taglish. Windows terms and labels
may keep their original names. Every family has examples in all three.
The sample phrases are starting points for additional paraphrase tests.

Use these common commands during early testing alongside the catalog:
  “Stop now” cancels pending input and releases held keys and mouse buttons.
  “Start the Ambient screensaver” enters fullscreen and ends voice capture.
  “I-on ang Dashboard screensaver” opens the fullscreen dashboard preset.
  Escape or physical input dismisses the saver and restores the desktop view.
  “Buksan ang command palette” shows locally available commands.
  “Click Save in Notepad” resolves the exact button in the named test app.
  “Paki-scroll down three notches” sends three notches to the current target.
  “May timer pa ba ako?” reads actual running timers from SQLite.
  “I-shut down ang PC” displays the power confirmation for the current request.
  “Sleep the PC” previews Windows sleep using a separate local power intent.
  “Sige, close Amica” ends Amica after an explicit exit request.
  “Gusto ko muna mag-type” switches input mode and preserves the conversation.
